# Git Introduction

Git is a distributed Version Control System (VCS) used to track changes in files and collaborate with multiple developers efficiently. It maintains the history of changes and allows reverting to previous versions when required. :contentReference[oaicite:1]{index=1}

--------------------------------------------------------

# Key Concepts

Repository (Repo)
Stores project files and complete version history.

Commit
A snapshot of project changes.

Branch
A separate line of development.

Merge
Combines changes from different branches.

Clone
Downloads a repository from a remote server.

Push
Uploads local commits to the remote repository.

Pull
Fetches and merges changes from the remote repository.

# Repository Commands

git init

Initialize a new repository.

git clone <repository_url>

Clone existing repository.

--------------------------------------------------------

# Branch Commands

git branch

List branches.

git branch feature

Create branch.

git checkout feature

Switch branch.

git checkout -b feature

Create and switch.

git branch -d feature

Delete merged branch.

git branch -M main

Rename branch to main.

--------------------------------------------------------

# Tracking & Commit Commands

git status

Shows repository status.

git add file

Stage one file.

git add .

Stage all files.

git rm --cached file

Unstage a tracked file.

git restore file

Discard uncommitted changes.

git commit -m "message"

Create a commit.

--------------------------------------------------------

# Remote Repository Commands

git remote add origin URL

Connect local repository.

git remote -v

View remotes.

git push -u origin main

Push and set upstream.

git push

Push changes.

git pull

Fetch latest changes.

--------------------------------------------------------

# History Commands

git log

View commit history.

git show COMMIT_ID

View commit details.

git revert COMMIT_ID

Undo a commit safely.

--------------------------------------------------------

# Merge Conflict

Occurs when multiple developers modify the same lines before syncing changes.

Conflict markers

=======

>>>>>>> branch-name

Resolve conflict manually, then:

git add .

git commit

# Fork vs Clone

Fork

Creates a copy of another repository in your own GitHub account.

Clone

Downloads a repository to your local machine while keeping it connected to the remote repository.

--------------------------------------------------------

# SSH Authentication

Generate SSH Key

ssh-keygen -t ed25519 -C "your@email.com"

Display Public Key

cat ~/.ssh/id_rsa.pub

Test Connection

ssh -T git@github.com

--------------------------------------------------------

# Git Best Practices

- Commit frequently with meaningful messages.
- Use feature branches.
- Pull latest changes before pushing.
- Never push directly to the production branch.
- Use Pull Requests for code review.
- Resolve merge conflicts carefully.
- Keep repositories synchronized.

- SSH authentication provides secure access to remote repositories.
